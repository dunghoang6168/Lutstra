# Lutstra: instructions for coding agents

Lutstra is a local-first desktop music player for lossless and Hi-Res libraries: Angular 21 in an Electron shell on Windows. The longer human guide is [docs/APP_GUIDE.md](docs/APP_GUIDE.md). The design system is [DESIGN.md](DESIGN.md), and its rules are binding.

## Hard rules
- **Stay in the UI layer unless the task says otherwise.** Do not change playback behaviour, `PlayerService` logic, gateways, `electron/`, IPC or the database.
- **No new dependencies.**
- **Angular style:** standalone components, signals and `computed`, `@if`/`@for` (never `*ngIf`/`*ngFor` in new code). Use external `.html` and `.scss` files (see [docs/FRONTEND_STRUCTURE.md](docs/FRONTEND_STRUCTURE.md)).
- **Tokens only.** Colours, spacing, radii, type, shadows and motion come from `src/styles/_tokens.scss` and `_themes.scss`. Do not hard-code values. If a value is missing, ask before adding a token.
- **Names:** the product is **Lutstra** and technical names use `lutstra`. Preserve the renderer origin `app://lutsra`, localStorage keys `lutsra.*` and IndexedDB name `lutsra-waveform` for existing browser data. Legacy profile migration also retains the old profile and database names to locate source data.
- **Keep accessibility:** real buttons and links, accessible names, visible focus, and the keyboard pattern described below.
- **Line endings:** keep LF.
- **Files to leave alone:** do not commit `docs/AUDIO_ENGINE_PLAN.md` or `skills-lock.json` unless asked.

## Design rules (full text in DESIGN.md)
- **Three layouts, one palette.** `html[data-layout]` is `inset` (Gallery), `classic` (Console) or `liquid-glass` (Ambient). Layouts change topology, never colour. Components read layout tokens (`--surface-radius`, `--control-radius`, `--row-height`, `--cover-*`, `--type-*`, `--motion-*`) instead of branching on layout.
- **Accent is meaning, not decoration.** It marks Hi-Res, active state, progress and focus. Accent text uses `--text-accent`. `--accent-primary` is for fills, rings and borders only. Do not use accent gradients or glows for ornament.
- **Amber means absence.** `--status-warning` / `--status-warning-text` are only for missing or unavailable files and disconnected outputs.
- **Ink play.** The play/pause control is `--text-primary` fill with a `--text-inverse` icon. Never accent, never glow.
- **Measurements are mono.** Format, bit depth and rate, kbps, times, counts and the signal path use the mono face with tabular figures. Prose never does. Format with `formatTrackFormat`, `formatResolution` and `trackQuality` in `src/app/features/home/library-quality.ts`. Hi-Res means lossless at 24-bit or above 48 kHz.
- **Type floor is 13px** (`--font-size-xs`). Console labels use `--type-label-variant` (small caps), never `text-transform: uppercase`.
- **Overlays:** text over artwork stays white on `--scrim-soft`, `--scrim-strong` or `--scrim-heavy`. Destructive buttons use `--status-error-fill`, `--status-error-fill-hover` and `--color-on-error`.
- **Copy:** sentence case everywhere: buttons, headings, aria-labels and tooltips. Page names (Home, Songs, Albums, Now Playing…) and engine names (Native Shared, Chromium Shared) keep their capitals. One item is a **track** ("Songs" only names the page).
- **Tooltips:** use `appTip` (icon-only controls and explanations; keep the aria-label) or `appTipOverflow` (truncated text, shown only while it overflows) from `src/app/shared/directives/tip.directive.ts`, never `title`. The one exception is the Gallery rail resize handle, where a cursor-anchored native tip suits a full-height strip.
- **Overflowing single lines in the Ambient dock** ping-pong with `appMarquee` (`shared/directives/marquee.directive.ts`, first child `.marquee-text`) and fall back to an ellipsis under reduced motion.
- **Playing cover art** goes through `app-cover-art` (`shared/components/cover-art`), which waits for the next cover to decode and crossfades to it at `--cover-fade-dur` (the layout's `--motion-dur`, 0ms in Console). Do not bind the playing track's artwork to a bare `<img>`.
- **One playback-mode control:** the Ambient dock and Gallery's Now Playing use one button that cycles Off → Shuffle → Repeat All → Repeat One (`PlayerService.playbackMode`, `playbackModeIcon`, `playbackModeLabel`, `cyclePlaybackMode()`): accent when on, a muted repeat glyph when off. The Console strip and the Gallery rail keep separate shuffle and repeat. S and R still toggle each.
- **Responsive:** respond to the `.main-content` container (`@container main-content (...)`, `cqi`), not the viewport, so Console's tree and inspector are accounted for.

## Track lists and keyboard
Every track table follows the same pattern: `role="grid"` with roving tabindex (one row in the tab order), ↑/↓/Home/End/PageUp/PageDown through `nextRowIndex` in `src/app/shared/utils/row-navigation.ts`, Enter for the row's main action, and Space left to global play/pause. Selection follows focus (`aria-selected`), and row actions are tabbable only on the active row. Songs and the album, artist and playlist detail tables also multi-select through `shared/utils/row-selection.ts`: Ctrl+click or Ctrl+Space toggles, Shift+click or Shift+arrows select a range, Ctrl+arrows move focus only, Ctrl+A selects all visible rows, and Esc collapses to the focused row. At least one row stays selected. From two selected rows, `app-track-selection-bar` covers the header. Row actions live in one `app-track-actions-menu` (⋯: Play next, Add to queue, Add to playlist…); both it and the selection bar open `app-add-to-playlist-dialog`, which marks playlists that already hold the tracks and asks before adding duplicates. Playlist detail adds tracks through `app-add-tracks-panel`, a non-modal right column (Songs / Albums / Artists / Folders, last tab saved as the `addTracksTab` setting) whose rows drag into the table with the `application/x-lutstra-tracks` payload. Detail pages read `route.paramMap`, not the snapshot, so a reused component reloads when the id changes.

## Developer mode
`DevModeService` (`lutsra.dev.enabled`) is turned on from Settings: while it is off, the "About Lutstra" heading is a button that opens `app-dev-mode-dialog`, which asks for the developer code (in `docs/APP_GUIDE.md`); while it is on, the About card shows an **Exit developer mode** button. It adds the guarded **Music Roulette** page (`/random-folder`; code, route and storage keys keep the "random folder" names), reached from a gacha-cards icon button beside Settings in every layout (`src/assets/icons/gacha_cards_{outline,solid}.svg`, drawn as a CSS mask so it takes `currentColor`; solid while on the page), never from the tabs or the sidebar, so it is not mistaken for Folders. Each folder row has a checkbox beside it (outside the row button); ticked folders, from anywhere in the tree and remembered in `lutsra.dev.randomFolder.checked`, replace the open folder as one shared source (`sourceTrackIds()` drops repeats), and the Roll button names them ("2 folders"). Under the subfolders, the open folder's own playable tracks are listed (cover, title, artist, tier chip, time); each row is a checkbox label, and ticked tracks (`lutsra.dev.randomFolder.checkedTracks`) join the ticked folders in the same source ("2 folders, 5 tracks"). Clear unticks both. A round (`RandomSessionService`) reveals a random track from the source with a case-opening reel (`random-reel`: Web Animations API, Skip, instant under reduced motion, Web Audio ticks scaled by player volume), then picks each next track on demand. The round plays as the player's external source (`player.playExternal()` with an `ExternalSource`: `next`, `peek`, `previous`), so the user's queue stays parked at its entry and position and still takes Add to queue / Play next; `player.backToQueue()` resumes it there, `stopExternal()` stops when the queue is empty, and playing anything from the library, or picking a queue entry, ends the round. The round keeps its own history (Previous / Next walk it, Previous restarts after 3 seconds) and picks one track ahead through `peek` for gapless and crossfade, unless the page will show a reel for it. Reel cells carry a rarity tier by cached YouTube views: `popularityTiers()` ranks each region (top-level folder under a music root, `trackRegions()`; `RANKED_WITH_LIBRARY` folders such as "Random ass" rank against the whole library) into `TIER_SHARES` 40 / 30 / 20 / 10% base / blue / red / gold, gold being the most viewed; the top `MYTHIC_SHARE` (2%) is tier 5, mythical, and gold keeps at most `GOLD_PER_ARTIST` (2) tracks per `leadArtist()`, the rest dropping to red; tracks without views are base. The page loads cached views through `PopularityFetchService.load()` and sets `RandomSessionService.tiers` from the whole library, so a track keeps its tier in every folder. Tiers are coloured with the `--rarity-1`…`--rarity-4` tokens; mythical has no colour of its own but a hologram, the registered `--holo-hue` (`holo-cycle` keyframes in `_primitives.scss`) driving `--holo-live: oklch(var(--holo-l) var(--holo-c) var(--holo-hue))` from one animation on the page element, so the reel cell, flash, card, chip and spectrum (`liveColor` input: re-reads its colour token every frame) all share one clock; `--rarity-holo` is a static rainbow for dots. Those tokens and the tier effects exist only for this developer page, where "accent means Hi-Res" does not apply. Each pick is a gacha roll (`rollTier()` / `drawTrack()`): rates 65 / 25 / 8.5 / 1.5%, soft pity from roll 40, gold-or-better guaranteed at 50, red at least every 10; a top roll is mythical on a `MYTHIC_CHANCE` (25%) flip and always on top roll `MYTHIC_GUARANTEE` (3) since the last mythical; the pity counters (`gold`, `red`, `mythic`) persist in `lutsra.dev.randomFolder.pity`. Rates scale with the source (`RateScale`, `RandomSessionService.libraryTiers` from `tierCounts()`): each tier's weight, and the mythic chance, is multiplied by its share of the source over its share of the library, so a folder of hits rolls its hits instead of handing its one base track the base rate, while a library-shaped source rolls at the listed rates. Reel filler is drawn at those rates without pity and never gold or mythical, so those show only when the pick is one, unless the source has fewer than `MIN_FILLER_TRACKS` (5) lower tracks, when the whole source fills the strip. The stop sound grows with the tier (ding, two notes for red, an arpeggio for gold, a longer shimmer for mythical); a gold winner's halo breathes three times, a mythical one flashes a hologram across the strip, and the result card of either gets a tinted rim (hologram for mythical). Reduced motion keeps the end states without animation. Under the strip, a bare `app-spectrum-visualizer` mirrors 40 bands (50 Hz–23 kHz) out from the pointer line and hangs down behind the result card, coloured with the rarity token of the playing track and hidden (`visibility`, so the layout holds) while the reel spins or the user's queue still plays (`showSpectrum`: the round is the active source) (`mirrored`, `flipped`, `bare`, `barCount`, `minHz`/`maxHz`, `colorVar`, `liveColor` inputs; defaults keep Now Playing unchanged). Options live in `app-random-options-dialog` (`lutsra.dev.randomFolder.options`): include subfolders, roll every track (silent instead while the page is closed or the window is hidden, and a reel the browser froze is settled by a timeout), no repeats in a round, and infinite roulette (only with no repeats: a used-up pool starts over, keeping the last pick out of the next one). The queue is hidden on the page only (`RightPanelService.queueHidden`). Elsewhere the queue drawer shows a "Roulette is playing" banner whose button reads **Back to queue**, or **Stop roulette** when the queue is empty (`player.backToQueue()` does both; leaving the round also clears the roll view, so the page returns to the folders with no reel or spectrum), and marks the parked entry "Resumes here" (`.parked`, not lit as playing); the result card has the same button under Roll again (`session.leave()`). While a round plays, `PlayerService.modesLocked` (an external source is active) hides shuffle and repeat in the player bar and Now Playing, ignores S/R, and plays as repeat off without touching the saved modes. Developer mode also adds YouTube views to Folders, the source of the Music Roulette rarity: a **Views** column and a **Fetch views** button (refetch the listed files) on the file table, on the toolbar **Fetch missing views** (every uncached track under the open folder) and a **No match** toggle (every unmatched track under the open folder, with its relative folder), and a **Fetching views** banner with **Stop** under the scan banner. Every finished scan also fetches the library's uncached tracks, and turning developer mode off stops a running fetch. `PopularityService` (`electron/services`) spawns the user-installed `yt-dlp` binary without a shell, about a hundred queries per process on the command line (yt-dlp misreads non-ASCII stdin on Windows), picks each upload with `pickVideo()` (`electron/utils/youtube-match.ts`; a remix, "…mix" or instrumental track only matches an upload that says so), caches it in the `track_popularity` table and streams `popularity:progress`; Stop kills the process tree. `PopularityFetchService` (`features/folders`, root-provided) holds the results so a library-wide fetch survives navigation (`popularity:get` / `popularity:fetch-batch` / `popularity:cancel`, `POPULARITY_GATEWAY`). `node scripts/popularity-report.mjs` reads the database read-only and writes the per-region view distribution to `plan/reports/popularity-distribution.md`. Keep developer-only UI behind this flag and out of the shortcuts help.

## Verify before you report
1. `npx ng build` and `npx vitest run` (all files under `tests/`). `*.spec.ts` is gitignored, so commit new test files with `git add -f`, or name them `*.spec.mts`.
2. `node scripts/check-accent-contrast.mjs` when you touch colour tokens.
3. Look at the real UI. With a dev server running, `env -u ELECTRON_RUN_AS_NODE npx electron scripts/ui-sweep.cjs` covers every route × 3 layouts × 2 themes × 1440/560 and must report 0 flagged pages. It does not measure text over images, so check those screenshots by eye.
4. In your own probes, inject a no-transition style before measuring. Hidden windows freeze CSS transitions and give false results.
5. Stop any dev server you started.

## Working alongside other agents
- Several agents may work at once. Work only in the folder and branch you were given (a git worktree for parallel work) and on the port you were given. Touch only the files the task names.
- **Do not commit, push, checkout, stash or reset** unless the task explicitly allows it. The reviewer merges.
- **Reply in Vietnamese (most important):** always talk to the user in Vietnamese, and write the files in `plan/` in Vietnamese too. Code, comments, commit messages and the English docs stay in English.
- **Working notes go in `plan/<type>/`:** every `.md` you create goes in the matching subfolder of `plan/` at the repo root (gitignored), never in a home or temp folder: `plans/` (plans, timelines), `prompts/` (prompts for other agents), `reports/` (task results, investigations), `reviews/` (code or design reviews), `notes/` (backlogs, drafts, anything else). This does not cover real project docs such as `docs/`.
- **Commit messages:** ask the user to approve the message before committing. Never add `Co-Authored-By`, a model name, or any AI attribution to commits or PR descriptions.
- Send a short plan first and wait for approval. In the final report, list changed files, test output, screenshots, any deviations from the task, and bugs you noticed outside scope. Copy before/after tables from `git diff`; do not reconstruct them.
